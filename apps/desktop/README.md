# DataFoundry Desktop — Electron App

**Electron wrapper** that bundles DataFoundry Enhanced (API + Web + CDL panels) into a single Windows desktop application.

## Layout

```
apps/desktop/
├── package.json          ← electron-builder config (NSIS + Portable installers)
├── src/
│   ├── main.mjs          ← Electron main process (single-instance lock, API spawn, window mgmt)
│   ├── preload.mjs       ← IPC bridge (window.dfd API)
│   ├── index.html        ← App shell (3 tabs: Workbench, CDL Panel, Status)
│   ├── styles.css        ← Brand-styled dark UI
│   └── renderer.mjs      ← DOM logic, IPC calls, CDL panel, Theorem 3 demo
└── build/
    ├── icon.png          ← 256x256 brand icon (generated by make-icon.mjs)
    └── make-icon.mjs     ← One-shot icon generator (no external deps)
```

## What it bundles

| Component | Path | Role |
|-----------|------|------|
| Electron main | `src/main.mjs` | Single-instance lock, API server spawn, window state, IPC |
| Renderer | `src/index.html` + `renderer.mjs` | Workbench iframe, CDL panel, Status panel |
| API server | `../apps/api/dist/index.js` | Spawned on 14500+ port |
| CDL module | `../packages/counterfactual/src/index.mjs` | Loaded via dynamic import |
| Docs | `../docs/` | Bundled as extraResources |
| Process utilities | `../scripts/{port-allocator,process-lock,dev-isolated}.mjs` | Bundled for log/debug |

## What it does

1. **Single-instance guard** — second launch focuses existing window
2. **Lock file** — `.run/desktop.lock` prevents two Electron processes from clobbering
3. **API server spawn** — `apps/api/dist/index.js` on a free port in 14500–14600
4. **Window state persistence** — size + position saved to `userData/window-state.json`
5. **CDL panel** — `regime-conditional decision J(u) = αΦ_sem + (1-α)Φ_cf` with live α slider
6. **Theorem 3 demo** — proves regime-conditional u*(Rₜ) strictly dominates uniform u
7. **Workbench iframe** — loads the running Web workbench on the API port (when present)
8. **Status tab** — shows app info, API URL, Electron/Chrome/Node versions, cwd
9. **Tray menu** — show window / open logs / open repo / restart / quit
10. **Graceful shutdown** — SIGTERM all children, 5s SIGKILL grace, lock cleanup

## Build & run

```powershell
# 1. Generate icon (one-time)
cd apps\desktop
node build\make-icon.mjs

# 2. Dev launch (uses existing build output from datafoundry-enhanced)
npm start

# 3. Package a directory build (fast, no installer)
npm run dist:dir
# Output: apps/desktop/dist/win-unpacked/DataFoundry Desktop.exe

# 4. Full installer build (NSIS + portable .exe)
npm run dist
# Output: apps/desktop/dist/DataFoundry Desktop-0.1.0-x64.exe
#         apps/desktop/dist/DataFoundry Desktop-0.1.0-portable.exe
```

## IPC API surface (window.dfd)

```js
const info = await window.dfd.getInfo();     // { name, version, electron, chrome, node, apiPort, apiUrl, cwd, userData, logs }
await window.dfd.openLogs();                  // opens .run/desktop/ in file manager
await window.dfd.openRepo();                  // opens repo root in file manager
await window.dfd.restart();                   // SIGTERM children + relaunch
const dec = await window.dfd.cdl.run({ regime, phiSem, phiCf });  // dynamic-import CDL, returns J(u)
```

## Process isolation guarantees

| Concern | Mechanism |
|---------|-----------|
| Two Electron instances | `app.requestSingleInstanceLock()` |
| API port collision | `allocatePort()` 14500–14600 |
| Children leak after crash | `before-quit` SIGTERM → 5s → SIGKILL |
| Window state loss | `userData/window-state.json` on close |
| Stale lock after force-kill | `process.kill(prev.pid, 0)` check on boot |

## What is NOT bundled

- The **TUI** (`apps/tui`) — runs in terminal only, can be invoked via repo CLI
- The **Datalink service** (`services/datalink`) — separate Node process, optional external
- External LLM API keys — read from `.env` on first launch (offline demo works for many features)

## First-launch UX

1. Electron window opens at 1400×900
2. API server boots on a free 14500+ port
3. Once `GET /healthz` returns 200, the iframe loads the workbench URL
4. CDL panel is interactive immediately (uses bundled CDL package, no API needed)
5. Status tab reflects API readiness
